# spotlight_tour

حزمة Flutter لعمل **جولة تعريفية (Feature Tour / Coach Marks)** داخل أي تطبيق، بنفس شكل وحركة
الجولة الموجودة في الفيديو المرجعي: تعتيم للشاشة، إطار ذهبي متوهّج حول العنصر المستهدف، نبضة
بيضاء متحركة، وبطاقة شرح داكنة فيها زر تخطٍّ وعدّاد «5 من 25» وأزرار السابق/التالي، مع دعم
كامل للعربية واتجاه RTL.

## المزايا

- إبراز أي ويدجت عبر `GlobalKey` بإطار مستطيل مدوّر أو دائري، مع توهّج ونبضة متحركة.
- إبراز **نطاق نصي داخل نص متدفّق** (`Text`/`RichText`) بإطار متدرّج يتبع سطور النص
  نفسها: يبدأ وينتهي منتصف السطر ويستثني ما قبل النطاق وما بعده، تماماً مثل تحديد
  النص، ويدعم العربية واتجاه RTL تلقائياً (`TourTargetShape.textLines` + `textRange`).
- **جولة تنفّذ إجراءات داخل التطبيق**، لا تكتفي بالشرح: زر «التالي» يستدعي نفس دوال
  تطبيقك (`onNext`/`onEnter`) — يفتح خيارات الآية الحقيقية، يقلب الصفحة، يغلق
  النافذة — ثم تكمل الجولة الشرح على النتيجة، بما فيها عناصر داخل النوافذ المنبثقة.
  وزر «السابق» يعيد تجهيز واجهة كل خطوة: `onExit` يُنفَّذ عند مغادرتها في أي اتجاه
  و`onEnter` عند الوصول ذهاباً وإياباً، فتُفتح النوافذ من جديد عند العودة إليها.
- **عرض قلب الصفحة تلقائياً** (`PageSwipeDemo`): قلب الصفحة الحقيقية كاملة
  يميناً أو يساراً بسرعة واضحة، ثم إعادتها إلى موضع المستخدم بالضبط — بديل عن
  طلب السحبة منه. يكفي وضع `swipeDemo` على الخطوة: الجولة تنتظر مهلة قصيرة
  بعد ظهورها (`settleDuration`) ليراها المستخدم، ثم تدير العرض والإلغاء بنفسها،
  ومؤشّر السحبة مربوط بالصفحة طوال ذلك: يميناً مع القلبة ويساراً مع العودة.
  وخطوات «جرّب بنفسك» ما زالت متاحة: تمرير اللمس الحقيقي
  (لمس/ضغط مطوّل/سحب) عبر التعتيم إلى الويدجت المستهدف، مع إخفاء زر «التالي» حتى
  ينفّذ المستخدم الإجراء فعلاً (`interaction` + `requireInteraction`).
- خطوات بدون هدف (مقدمة وخاتمة) تظهر البطاقة في منتصف الشاشة.
- انتقالات متحركة: انزلاق البطاقة للأسفل عند الخروج، انزلاق الإطار بسلاسة بين العناصر،
  ثم ظهور البطاقة الجديدة من الأسفل.
- موضع البطاقة تلقائي: تحت الهدف إن كان أعلى الشاشة، فوقه إن كان أسفلها، وإلا أسفل الشاشة.
- كل النصوص والألوان والمدد قابلة للتخصيص (`TourLabels` و `SpotlightTourTheme`).
- تعمل مع LTR وRTL تلقائياً حسب اتجاه الشاشة.

## الاستخدام

1. أضف `GlobalKey` لكل ويدجت تريد إبرازه:

```dart
final searchKey = GlobalKey();
final verseKey  = GlobalKey();
```

2. عرّف الخطوات وأنشئ الكنترولر:

```dart
late final tour = SpotlightTourController(steps: [
  const TourStep(                                   // خطوة بدون هدف = مقدمة بالمنتصف
    title: 'جولة في التطبيق',
    description: 'جولة قصيرة نتعرف فيها على أهم أجزاء الشاشة.',
  ),
  TourStep(
    targetKey: verseKey,
    title: 'اضغط مطولاً على أي آية',
    description: 'يفتح درجاً فيه التفسير والاستماع دون أن تغادر الصفحة.',
    icon: Icons.touch_app_outlined,                 // أيقونة صغيرة بجانب العدّاد
  ),
  TourStep(
    targetKey: searchKey,
    title: 'ابحث',
    description: 'اكتب كلمة من الآية وانتقل إليها بلمسة.',
    shape: TourTargetShape.circle,                  // إطار دائري بدل المستطيل
    targetPadding: EdgeInsets.all(6),
  ),
  const TourStep(
    title: 'هذا كل شيء',
    description: 'تجد هذه الجولة في الإعدادات متى ما أردت إعادتها.',
  ),
]);
```

3. لفّ شاشتك بـ `SpotlightTour` وابدأ الجولة متى شئت:

```dart
@override
Widget build(BuildContext context) {
  return SpotlightTour(
    controller: tour,
    child: Scaffold(...),
  );
}

// مثلاً عند أول تشغيل:
WidgetsBinding.instance.addPostFrameCallback((_) => tour.start());
```

### إبراز نطاق نصي عبر السطور

لإبراز آية أو جملة داخل نص أطول متدفّق (كما في صفحات المصحف)، ضع المفتاح على ويدجت
النص نفسه واستخدم `TourTargetShape.textLines` مع `textRange` (إزاحات الأحرف داخل
النص، مثل `TextSelection`). إن لم تحدد `textRange` يُبرَز النص كله:

```dart
const pageText = '...نص الصفحة كاملاً هنا...';
final pageTextKey = GlobalKey();

Text(pageText, key: pageTextKey, ...)

final start = pageText.indexOf('وَاللَّهُ');
final end = pageText.indexOf('﴿٨٧﴾') + '﴿٨٧﴾'.length;

TourStep(
  targetKey: pageTextKey,
  shape: TourTargetShape.textLines,
  textRange: TextRange(start: start, end: end),
  title: 'اضغط مطولاً على أي آية',
  description: 'يفتح درجاً فيه التفسير والاستماع.',
)
```

الإطار الناتج متدرّج: يحيط بكل سطر بحدوده الفعلية، فيبدو النص المحدد وكأنه مظلَّل
بإطار واحد متصل، ويبقى النص خارج النطاق معتَّماً حتى لو شارك نفس السطر.

قيود هذا الشكل:

- يعمل فقط مع ويدجت `Text` أو `RichText` (وليس أي ويدجت)، ويجب أن يكون المفتاح على
  ويدجت النص نفسه، وأن يكون النص ظاهراً ومُنسَّقاً على الشاشة.
- لا يدعم `WidgetSpan` (عناصر مضمّنة داخل النص) بشكل دقيق.
- أثناء الانتقال من خطوة لأخرى ينزلق الإطار **سطراً بسطر**: كل سطر من المحيط
  المتدرّج ينتقل من موضعه السابق إلى موضعه الجديد، فيحافظ الإطار على شكله
  المتدرّج المحيط بالنص طوال الحركة — بلا مستطيل وسيط وبلا تداخل لوني
  (cross-fade) مضلل، وبلا قفزة عند نهاية الحركة.
- إذا تقدّمت الجولة والهدف ما زال يتحرك (قلب صفحة لم يستقر بعد، أو نافذة
  منبثقة ما زالت تنزلق)، يتتبّع الإطار الويدجت الحقيقي إطاراً بإطار حتى
  يستقر، فلا يتجمّد الإطار على موضع قديم بعيداً عن النص.
- العرض يُحسب من التنسيق الفعلي للنص (مربعات الحروف نفسها، التي قد تتجاوز
  عرض الفقرة قليلاً عند نقاط الالتفاف)، لذا يتبع المحاذاة والاتجاه
  (RTL/LTR) تلقائياً.


### جولة تنفّذ إجراءات (لا تشرح فقط)

#### 1) زر «التالي» ينفّذ نفس دالة تطبيقك

اربط الخطوة بنفس الدالة التي يستدعيها التفاعل الحقيقي في تطبيقك. تُنتظَر الدالة قبل
الانتقال، فإن فتحت واجهة جديدة (نافذة خيارات مثلاً) وُجدت قبل أن تبحث الخطوة التالية
عن هدفها داخلها:

```dart
TourStep(
  targetKey: pageTextKey,
  shape: TourTargetShape.textLines,
  textRange: verseRange,
  title: 'خيارات الآية',
  description: 'الضغط المطوّل على أي آية يفتح خياراتها. اضغط «التالي» وسنفتحها لك.',
  onNext: () => unawaited(openVerseOptions()),   // نفس دالة الضغط المطوّل في تطبيقك
),
TourStep(
  targetKey: tafsirKey,        // ويدجت داخل النافذة المنبثقة نفسها
  title: 'التفسير',
  description: 'من هذه القائمة تفتح التفسير مباشرة.',
  onEnter: () => unawaited(openVerseOptions()), // تعيد فتحها عند العودة بـ«السابق»
  onNext: closeVerseOptions,   // إغلاق النافذة قبل متابعة الجولة
  onExit: closeVerseOptions,   // وإغلاقها عند مغادرة الخطوة في أي اتجاه
),
```

- `onNext`: تُنفَّذ عند ضغط «التالي/ابدأ/تم» في هذه الخطوة (وللأمام فقط)، وتُنتظَر
  إن أعادت `Future`. أثناء التنفيذ والانتقال تتعطّل أزرار التنقل مع مؤشر انتظار،
  وتُتجاهل الضغطات المتكررة، ويبقى «تخطي الجولة» فعّالاً.
- `onEnter`: تُنفَّذ عند وصول الخطوة (ذهاباً وإياباً) قبل حساب الإطار؛ مناسبة
  لتحضير الواجهة. اجعلها idempotent. **وهذا هو مفتاح الرجوع الصحيح:** أي واجهة
  تحتاجها الخطوة افتحها هنا، فيعيد «السابق» تجهيزها تلقائياً بدل أن يعرض شرحاً
  عن واجهة غير موجودة.
- `onExit`: تُنفَّذ عند مغادرة الخطوة في أي اتجاه (التالي/السابق/التخطي/تم)
  وتُنتظَر؛ ضع فيها إغلاق ما فتحه `onEnter` (عرض قلب الصفحة المربوط بـ
  `swipeDemo` تلغيه الجولة بنفسها عند المغادرة). خطوتان متتاليتان داخل نفس
  النافذة: كلتاهما تفتحها في `onEnter` (الدالة الآمنة التكرار تجعل الثانية
  لا-عملية) والأخيرة فقط تغلقها في `onExit`.
- **مهم:** إن فتحت `showModalBottomSheet` فلا تُعِد الـ Future الخاص بها (يكتمل
  عند *إغلاق* النافذة)، بل شغّل الفتح فقط (`unawaited`)؛ الحزمة تنتظر ظهور الهدف
  التالي تلقائياً حتى `targetTimeout` (افتراضياً 1.2 ثانية، قابل للتعديل لكل خطوة).
- **الطبقات:** عندما تفتح إجراءات الخطوة BottomSheet أو Dialog ترتفع الجولة تلقائياً
  فوقه، فيمكن إبراز عناصر داخله بمفاتيحها كأي ويدجت آخر.
- الحزمة لا تكتشف أفعال تطبيقك تلقائياً؛ اربط كل خطوة بنفس دوال تطبيقك أنت.

#### 2) عرض قلب الصفحة تلقائياً ثم العودة لصفحة المستخدم (`PageSwipeDemo`)

الأسلوب الأنسب عادةً لتعليم قلب الصفحة: بدل أن تطلب من المستخدم أن يسحب
بنفسه، تقلب الجولة الصفحةَ الحقيقية كاملة يميناً بسرعة واضحة، تتوقف لحظة،
ثم تعيدها إلى الموضع الذي كان يقف عليه بالضبط:

```dart
// في State الشاشة (مع TickerProviderStateMixin):
late final swipeDemo = PageSwipeDemo(pageController: pageController, vsync: this);
// وفي dispose: swipeDemo.dispose();

TourStep(
  targetKey: pageViewKey,
  title: 'قلّب الصفحات',
  description: 'تنقّل بالسحب يميناً أو يساراً، كما تقلب الصفحة نفسها الآن أمامك.',
  indicator: TourIndicator.swipeLeftToRight,   // اتجاه السحبة المعروضة
  swipeDemo: swipeDemo,   // هذا كل الربط المطلوب: الجولة تدير العرض بنفسها
),
```

- **الجولة تدير العرض بنفسها:** ما دام `swipeDemo` على الخطوة لا تحتاج أي
  ربط في `onEnter`/`onExit`. عند وصول الخطوة تنتظر الجولة
  `settleDuration` (افتراضياً 1000ms) والصفحة ساكنة — ليرى المستخدم بطاقة
  الخطوة وإطارها أولاً، والمؤشّر واقف عند حافة البداية يخفت ظهوراً — ثم
  تقلب الصفحة باتجاه `indicator`. وعند مغادرة الخطوة (التالي/السابق/
  تخطٍّ/إنهاء) يُلغى العرض الجارٍ وتعود الصفحة فوراً. الربط اليدوي القديم
  ما زال يعمل (`demonstrate` لا-عملية أثناء العرض و`cancel` آمنة دائماً)،
  و`autoRunSwipeDemo: false` يترك التشغيل لك إن أردت لحظة مخصصة.
- القلب كامل وبإيقاع مقروء: `turnDuration` (افتراضياً 850ms) لكل اتجاه
  و`holdDuration` (افتراضياً 450ms) وقوفاً على الصفحة المقلوبة، والعودة تتم
  إلى **إزاحة البداية نفسها** مهما كانت الصفحة (لا يُفترض أنها الصفحة صفر).
- القلب الكامل يعبر حدود الصفحة، فيُطلق `PageView` ردّ `onPageChanged`
  مرتين (ذهاباً وعودة). إن كان تطبيقك يحدّث حالته من `onPageChanged` فتجاهل
  النداءات أثناء العرض: `if (swipeDemo.isRunning) return;`
- المؤشّر مربوط بالصفحة طوال الخطوة: واقف عند حافة البداية أثناء المهلة،
  منزلق مع القلبة في اتجاهها، ثم عاكس اتجاهه مع قلبة العودة، وبعد انتهاء
  العرض يهدأ بدل أن يقفز إلى دورة مؤشر منفصلة. إن تعذّر العرض (تقليل
  الحركة — لا يعمل تلقائياً حينها — أو حافة تمرير بلا مجال) رجع المؤشر
  لدورانه المعتاد.
- الاتجاه يُحسب من اتجاه المحور الفعلي: `leftToRight` يحرّك المحتوى يميناً
  في RTL وLTR على السواء. وعند حافة التمرير حيث لا توجد صفحة كاملة في
  الاتجاه المطلوب (مثلاً آخر صفحة في المصحف مع سحبة لليمين) لا يتحرك
  إطلاقاً بدل أن يُري السحبة المعاكسة، ويبقى مؤشّر الاتجاه هو الشرح.
- يعمل عبر `AnimationController` خاص به (يحتاج `vsync`)، ولا يستخدم
  `animateTo` حتى لا يتنازع مع سحبة المستخدم أو يعلق أثناء التخلص من الشاشة.

#### 3) خطوات «جرّب بنفسك»: انتظار التفاعل الحقيقي

لتعليم السحب أو الضغط المطوّل فعلياً، مرّر اللمس عبر التعتيم إلى الويدجت المستهدف
وأخفِ زر «التالي»، ثم تقدّم الجولة من معالج تطبيقك نفسه:

```dart
TourStep(
  targetKey: pageViewKey,
  title: 'قلّب الصفحات',
  description: 'اسحب الصفحة يميناً أو يساراً للتنقل. جرّب الآن بنفسك.',
  interaction: TourTargetInteraction.swipe,   // يمرّر السحب إلى PageView الحقيقي
  requireInteraction: true,                    // لا زر «التالي»؛ تلميح بدلاً منه
  interactionHint: 'اسحب الصفحة للمتابعة',
  indicator: TourIndicator.swipeLeftToRight,   // مؤشّر يُري السحبة نفسها
),

// وفي تطبيقك — نفس المعالج الحقيقي:
onPageChanged: (page) {
  if (tour.status == TourStatus.running && tour.index == swipeStepIndex) {
    tour.next();   // المستخدم نفّذ الإجراء فعلاً، تتقدم الجولة
  }
},
```

قيم `interaction`: `tap` (لمس)، `longPress` (ضغط مطوّل ولمس)، `swipe` (سحب ولمس).
داخل الإطار يصل اللمس إلى تطبيقك، وخارجه يبقى محجوباً. عند `requireInteraction`
يظهر تلميح بدل زر «التالي» (نصه الافتراضي في `TourLabels.interactionHint`).

#### مؤشّر السحب المتحرك

المؤشّر الافتراضي نبضة تلميح (`TourIndicator.pulse`). على خطوة تعلّم قلب
الصفحة استخدم بدلها مؤشّراً يتحرك فعلياً بعرض الهدف ليُري اتجاه السحبة:

- `TourIndicator.swipeLeftToRight`: نقطة بيضاء تنزلق من يسار الهدف إلى
  يمينه مع ذيل خافت يتبعها (مثل قلب صفحة المصحف)، ثم تتلاشى وتتكرر.
- `TourIndicator.swipeRightToLeft`: نفس الحركة بالاتجاه المعاكس.

المؤشّر لا يعيق اللمس أبداً: السحبة الحقيقية تمرّ إلى تطبيقك كما هي. ويخضع
لنفس قواعد النبضة: يتوقف بعد `pulseRepeatCount` دورات (الافتراضي 4)،
ويُخفى تماماً مع إعداد «تقليل الحركة» في النظام أو مع `showPulse: false`,
ويُرسَم داخل `RepaintBoundary` خاص به فلا يعيد رسم تعتيم الشاشة أثناء حركته.

### الجولة مرة واحدة فقط، وجولة لكل قسم

في تطبيق كبير متعدد الأقسام، أعطِ كل قسم كنترولر خاصاً به بمعرّف ثابت، وابدأ
جولته بـ `startOnce()` فتظهر تلقائياً أول مرة فقط، مستقلة عن بقية الأقسام:

```dart
final tourStore = GetStorageTourCompletionStore(GetStorage()); // انظر الأسفل

late final tour = SpotlightTourController(
  steps: mySteps,
  tourId: 'mushaf',              // معرّف ثابت لكل قسم: 'mushaf'، 'audio'، ...
  completionStore: tourStore,
);

// عند فتح الشاشة:
WidgetsBinding.instance.addPostFrameCallback((_) => tour.startOnce());

// زر «أعد الجولة» في الإعدادات:
await tourStore.reset('mushaf');
tour.start();
```

- الإكمال يُسجَّل عند «تم»، وعند «تخطي الجولة» أيضاً إلا إن عطّلت ذلك بـ
  `markCompletedOnSkip: false`.
- `TourCompletionStore` واجهة من ثلاث دوال فقط، بدون أي اعتمادية جديدة: طبّقها
  فوق التخزين الموجود أصلاً في تطبيقك. المثال الجاهز على `get_storage` موجود في
  توثيق الكلاس، والحزمة تتضمّن `InMemoryTourCompletionStore` للاختبارات.

### كنترولر واحد لكل التطبيق (استدعاء مركزي)

إن أردت كنترولراً واحداً تستدعيه من أي مكان — أي صفحة أو خدمة — ركّب
`SpotlightTourHost` مرة واحدة في `builder` أعلى الـ Navigator، واحتفظ
بالكنترولر في خدمة دائمة:

```dart
// خدمة دائمة (GetX service أو Provider أو متغير عام):
class TourService extends GetxService {
  final tour = SpotlightTourController(completionStore: tourStore);
}

GetMaterialApp(
  builder: (context, child) => SpotlightTourHost(
    controller: Get.find<TourService>().tour,
    child: child!,
  ),
  home: const HomePage(),
);

// من أي شاشة أو قسم، بخطوات ذلك القسم:
Get.find<TourService>().tour.start(tourId: 'mushaf', steps: mushafSteps);

// وجولة أول مرة لكل قسم على نفس الكنترولر:
Get.find<TourService>().tour.startOnce(tourId: 'settings', steps: settingsSteps);
```

- السِّتر والبطاقة يرتفعان فوق كل المسارات: الصفحات المفتوحة بـ `Get.to`
  أو `Navigator.push` والحوارات والقوائم المنبثقة، فلا حاجة لتغليف كل شاشة.
- تستطيع خطوة أن تعبر الصفحات: انتقل في `onEnter` (أو `onNext`) إلى الصفحة
  المطلوبة، وستجد الجولة هدفها هناك بعد استقرار الصفحة (ضمن `targetTimeout`).
- استدعاء `start` أثناء جولة ظاهرة يستبدلها بأمان: تُنفَّذ `onExit` للخطوة
  الحالية (دون `onNext`) ثم تبدأ الجولة الجديدة. وأثناء انتقال جارٍ يُتجاهل
  الاستدعاء كأزرار التنقل.
- القواعد: مضيف واحد فقط لكل كنترولر (تنبيه debug يمنع التكرار)؛ كل هدف يجب
  أن يكون مركّباً على الشاشة عند وصول خطوته وإلا ظهرت البطاقة بلا إطار؛ وكل
  `GlobalKey` مرتبط بويدجت واحد ظاهر. الكنترولر المركزي عمره عمر التطبيق،
  فلا تتخلص منه مع أي شاشة.
- استخدام `SpotlightTour` لكل شاشة (النمط السابق) ما زال يعمل كما هو، وبنفس
  الكنترولر لا تجمع النمطين.

### الأداء والحركة

- **لا تكلفة وأنت لا تعرض جولة:** `SpotlightTour` لا يدرج أي Overlay ولا يشغّل
  أي AnimationController قبل `start()`؛ وجوده حول شاشتك لا يكلّف شيئاً.
- **النبضة معزولة ومتوقفة تلقائياً:** أثناء النبضة يُعاد رسم طبقة صغيرة حول
  الهدف فقط، لا كامل الشاشة، وتتوقف بعد `pulseRepeatCount` دورات (الافتراضي 4؛
  `null` = بلا توقف، `0` = بلا نبضة).
- **التوهّج قابل للتخفيف:** `glowSigma: 0` يلغي الـ blur (أغلى عملية رسم في
  الحزمة) ويبقي الإطار الحاد — مناسب للأجهزة الضعيفة.
- **يحترم «تقليل الحركة»:** عند تفعيلها في إعدادات النظام: بلا نبضة، انتقال
  فوري للإطار، واكتفاء بتلاشٍ قصير للبطاقة — تلقائياً دون أي كود منك.
- **دخول متدرّج لمحتوى البطاقة:** العنوان ثم الوصف ثم الأزرار بلطف؛ عطّله بـ
  `contentStagger: false` في الثيم.
- نصيحة للتطبيقات الثقيلة: أوقف حركات شاشتك الدائمة (Lottie وجزيئات وغيرها)
  بينما الجولة ظاهرة، فهي تعمل تحت التعتيم دون فائدة.

### ردود الأفعال

```dart
tour
  ..onFinish = () => markTourSeen()      // ضغط «تم» في آخر خطوة
  ..onSkip   = () => markTourSeen()      // ضغط «تخطي الجولة»
  ..onStepChanged = (i) => debugPrint('step $i');
```

```dart
SpotlightTour(

```

#### ستايل خاص لكل خطوة (`TourStep.style`)

أي خطوة تقبل `style: TourStepStyle(...)` يخصّص مظهرها هي فقط؛ كل حقل تتركه
`null` يرجع لثيم الجولة، والخطوات بلا `style` تبقى على الثيم كما هي. الأنماط
النصية تُدمج فوق أنماط الثيم (`TextStyle.merge`) فيكفي أن تمرّر ما تريد
تغييره، والألوان والقيم الأخرى تحل محل الثيم عند تحديدها.

```dart
TourStep(
  targetKey: audioKey,
  title: 'المشغل',
  description: 'استمع للتلاوة من هنا',
  style: const TourStepStyle(
    accentColor: Colors.teal,                        // إطار وتوهّج وزر هذه الخطوة
    cardColor: Color(0xFF0E2A28),                    // خلفية بطاقتها
    titleStyle: TextStyle(color: Colors.tealAccent), // تندمج فوق نمط العنوان
    borderWidth: 3,
  ),
)
```

يمكنك تخصيص: `scrimColor`, `cardColor`, `accentColor`, `onAccentColor`,
أنماط العنوان والوصف والعدّاد والتخطّي والسابق وزر التأكيد، `cardRadius`,
`cardPadding`, `cardMargin`, `borderWidth`, `glowSigma`, `targetGap`،
و`primaryButtonHeight`. مدد الحركة وإعدادات النبض تبقى من ثيم الجولة.

### ملاحظات

- إن لم يظهر الويدجت المستهدف خلال `targetTimeout` (افتراضياً 1.2 ثانية من بدء
  الخطوة) يُرسم الشرح بدون إطار. الأهداف داخل ListView غير الظاهرة حالياً لا يمكن
  إبرازها.
- إن تخطّى المستخدم الجولة بينما فتحتَ نافذة من داخل خطوة، أغلقها من `onSkip`
  (وكذلك `onFinish`) كما في المثال.
- إن كانت شاشتك داخل `Directionality` خاص بها، تلتقط الحزمة اتجاهها تلقائياً.
- لإعادة الجولة زرّياً: `tour.start()` في أي وقت. ولجولة تلقائية أول مرة فقط
  استخدم `startOnce()` مع `tourId` (انظر قسم «الجولة مرة واحدة فقط»).
